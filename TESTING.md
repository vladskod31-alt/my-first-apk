# Проверка LIBO 2.0.0-beta.1

Проверки выполняются локально; активного GitHub Actions workflow пока нет (подключению не хватает разрешения `workflows`). Шаблон CI находится в `ci/android.yml`.

## Выполнено

- `npm test`: 17 unit-тестов. Валидность кодов/пакетов, защита от лишних полей, ограничения длины, запрещённые SVG/внешние изображения, безопасные адреса signaling/TURN, экспорт без приватной конфигурации.
- `npm run test:e2e`: 6 сценариев Chromium / Playwright.
  - Настоящая пустая стартовая страница, без вымышленных контактов, генерация QR.
  - «Избранное», литеральный HTML (не исполняется), черновики, поиск, тема и перезагрузка.
  - Мобильный экран 360 px, навигация назад, проверка личного кода, отсутствие горизонтального переполнения.
  - Скачивание текстового экспорта без идентификатора профиля и настроек подключения.
  - **Два изолированных браузерных профиля** обмениваются текстом, подтверждением сохранения, ответом и декодируемой фотографией по **настоящему WebRTC DataChannel**, через локальный тестовый signaling.
  - Сообщение остаётся в очереди, когда получатель закрыт; переживает перезагрузку отправителя и приходит один раз после возвращения получателя.
- `npm run build`: production bundle со всеми JS/CSS/шрифтами локально.
- Извлечённые из готового APK assets проверены в Chromium на origin `https://appassets.androidplatform.net` с отключённой внешней сетью: запуск, локальное сохранение после перезагрузки и JS-обработчик Android Back работают. Native bridge в этой проверке имитируется; это не запуск на Android.
- `scripts/build-apk-local.sh`: AAPT2 → ECJ → D8 → ZIP alignment → подпись APK.
- `apksigner verify`: RSA 2048, APK Signature Scheme v2 и v3; `zipalign -c 4` и ZIP integrity проходят.
- `aapt2 dump badging`: пакет `app.libo.messenger.beta`, launch activity `app.libo.messenger.MainActivity`, minSdk 26, targetSdk 35, разрешение только `INTERNET`, версия 2.0.0-beta.1.

## Что не подтверждено

- На физическом Android-телефоне и Android-эмуляторе APK в этой среде **не запускался**. Проверка подписи/упаковки не заменяет реальное тестирование Android lifecycle, клавиатуры, системного выбора фото и экспорта.
- Android lint через Gradle не выполнен: SDK/Gradle download domains недоступны из текущей среды; шаблон CI включает lint для следующего запуска после восстановления доступа.
- Публичный PeerJS-сервер и соединения между разными мобильными операторами не тестировались в этой среде. E2E использует локальный signaling и реальные WebRTC-каналы на одном хосте. Наличие TURN в строгих сетях не гарантируется.
- Аудит безопасности, нагрузочное тестирование, фоновые push и подтверждённое сквозное шифрование личности не заявляются.

## Повторить

```sh
npm ci
npm test
npm run test:e2e
node scripts/bootstrap-toolchain.mjs  # Linux x64; нужны gh, tar, Node 22
# Установите JAVA_HOME и LIBO_TOOLCHAIN из вывода предыдущей команды.
./scripts/build-apk-local.sh
```

У каждого APK есть отдельный SHA-256 в `SHA256SUMS.txt`. Тестовый ключ хранится вне Git; у будущей сборки может быть другой сертификат. Смотрите предупреждение об обновлениях в README и release notes.
