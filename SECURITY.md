# Безопасность LIBO

Сводка по версии **2.8.3**. Документ обновляется каждым релизом; подробные материалы:

- [SECURITY_ARCHITECTURE.md](SECURITY_ARCHITECTURE.md) — архитектура, примитивы, иерархия
  ключей, путь сообщения, схемы;
- [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md) — модель угроз
  (угроза / атака / защита / остаточный риск);
- [docs/SECURITY_AUDIT.md](docs/SECURITY_AUDIT.md) — чек-лист самопроверки с доказательствами;
- [docs/SECURITY_EVIDENCE.md](docs/SECURITY_EVIDENCE.md) — таблица доказательств по функциям.

⚠️ Независимый (внешний) аудит криптографического кода **не проводился**. Формулировки
«система безопасна» или «взломать невозможно» здесь не используются осознанно: заявления
ограничены тем, что подтверждено кодом и тестами.

## Что сделано в 2.8.3

| Угроза | Что сделано |
| --- | --- |
| Прослушивание переписки | Сообщения идут только внутри конверта ChaCha20-Poly1305 (E2EE v3, `web/lib/security.mjs`); сервера переписки нет, сигнальный сервер видит только адреса |
| Подмена собеседника (MITM) | Подпись Ed25519 по транскрипту рукопожатия, закрепление ключа (TOFU), отпечаток и код сверки в диалоге «Безопасность соединения», остановка сессии при смене ключа (`COMPROMISED`) |
| Подмена/повтор сообщения | Тег AEAD + подпись Ed25519 + окно повторов по `messageId` и времени |
| Компрометация ключа | Double Ratchet: ключ на каждое сообщение, эфемерные пары X25519, ротация цепочки (200 сообщений / 12 часов), forward secrecy |
| Кража устройства и файлов | Записи базы AES-256-GCM, ключ — в Android Keystore (StrongBox, когда доступен) или неизвлекаемый `CryptoKey`; PIN-замок с PBKDF2-SHA-256 (310 000) и ограничением попыток |
| Скриншоты и превью | `FLAG_SECURE` для приватных экранов (APK) |
| Утечка через логи и ошибки | `SecureLogger` вырезает секреты, отладка выключена в релизе; пользователю — только безопасный текст (`sanitizeError`) |
| Внедрённый код в WebView | Локальный origin, строгая CSP, запрет файлового доступа, мост `LiboAndroid` только для кода приложения |
| Перебор PIN и флуд | `RateLimiter`: 5 попыток/60 с, 60 сообщений/60 с |
| Подмена APK | Подпись v2 + v3 и опубликованный SHA-256 файла; проверка `apksigner verify` |

## Чего нет (честно)

- серверной аутентификации (аккаунты, refresh-токены, отзыв устройств, MFA, админ-API) —
  сборка P2P, у каждого устройства собственный ключ;
- Argon2id (в WebCrypto недоступен; используется PBKDF2-SHA-256 с большим числом итераций);
- Tor/альтернативного транспорта и защиты метаданных от сигнального сервера;
- биометрической привязки ключа Keystore (`BiometricPrompt`);
- независимого аудита.

Подробности и план — в [KNOWN_ISSUES.md](KNOWN_ISSUES.md).

## Подпись сборок

- Релизный ключ владельца: RSA-4096, SHA256withRSA, схемы v1 + v2 + v3, создан 12.09.2026
  вне Git. Ключ не хранится в репозитории: `.gitignore` запрещает `*.jks`, `*.keystore`,
  `*.p12`, `.env*`. В CI подпись берётся из секретов `LIBO_KEYSTORE_BASE64`,
  `LIBO_KEYSTORE_PASSWORD`, `LIBO_KEY_ALIAS`; без них `release.yml` не публикует APK как
  релизный.
- **APK 2.8.3 в этом репозитории собран в песочнице и подписан временным тестовым ключом
  песочницы**, а не ключом владельца. Отпечаток и SHA-256 указаны в
  [RELEASE_NOTES.md](RELEASE_NOTES.md). Android не устанавливает APK с другим ключом поверх
  установленного: перед установкой сделайте экспорт текста, удалите прежнюю версию и
  импортируйте копию после установки.
- Проверка: `apksigner verify --verbose --print-certs LIBO-2.8.3.apk` (сверьте
  `Signer #1 certificate SHA-256 digest`) либо сведения о сертификате в установщике Android.

### Ротация ключа

1. Создайте новый keystore и сохраните его вне Git (файл + пароль в секреты CI).
2. Опубликуйте новый отпечаток в RELEASE_NOTES.md и SECURITY.md **до** публикации APK.
3. Смените пакет приложения или явно предупредите, что обновление потребует
   переустановки: Android не принимает APK с другим ключом поверх установленного.
4. Старый ключ отзовите из документации, но не удаляйте исторические релизы: их подписи
   нужны для проверки уже скачанных файлов.

## Аудит секретов

`python3 scripts/scan-secrets.py` перебирает все blob'ы всех веток и тегов и ищет PEM-ключи,
JKS/PKCS#12-контейнеры, буквенные пароли, токены GitHub и ключи AWS. Результат на
22.09.2026: 54 blob'а, находок нет. Ссылки вида `-storepass env:NAME` считаются
безопасными (пароль берётся из окружения, а не из файла).

## Сообщение об уязвимости

Не создавайте публичное issue для уязвимостей. Напишите приватно владельцу репозитория
через GitHub (кнопка «Report a security vulnerability» на странице Security репозитория,
если включена private vulnerability reporting, либо личное сообщение владельцу), указав:
версию приложения и тег релиза, способ воспроизведения, затронутый компонент
(`web/`, `app/`, протокол), оценку воздействия. Подтверждение — в течение недели;
исправление публикуется релизом с пометкой security и обновлением этого файла.
