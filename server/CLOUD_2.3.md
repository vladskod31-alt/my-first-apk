# LIBO Cloud 2.3 — сервер доставки и истории

**Это готовая к настройке серверная часть, а не уже включённый хостинг.** Пользователь выбрал подготовить APK и сервер без развёртывания. Оба собеседника должны один раз подключить один и тот же постоянный HTTPS-сервер.

## Что работает после подключения

- Сервер принимает подписанные AES-256-GCM конверты и фиксирует их в SQLite до ответа `stored`.
- Получатель может быть не в приложении или временно без интернета. Конверт остаётся на сервере и загружается после подключения. Отправитель после статуса с облаком может закрыть приложение.
- Отдельная зашифрованная копия сохраняется для отправителя. Историю можно восстановить с новым устройством, используя свой файл ключа восстановления.
- Приватный ключ сообщения и секрет восстановления не передаются серверу открытым текстом. Сервер видит адреса/ники, время, размеры и типы служебных конвертов.
- Android-служба получает **только счётчик событий** по отдельному ограниченному токену и показывает общее уведомление. Она не знает ключи переписки и не может читать историю через API.
- Доставка и прочтение — разные статусы: очередь на устройстве → сохранено на сервере → сохранено клиентом получателя → показано в принятом чате.

Это не Signal Double Ratchet. Асинхронный режим использует постоянный ключ ECDH получателя и новый временный ключ отправителя на каждый конверт. Компрометация постоянного ключа получателя угрожает ранее записанным конвертам. Нужен независимый аудит до применения в ситуациях с серьёзными угрозами.

## Быстрый запуск на своём VPS

Требуются домен, Docker Compose и доступ к портам 80/443. Это отдельная инфраструктура: APK не создаёт сервер и не оплачивает хостинг.

1. Перенесите серверный архив на свой хост, распакуйте его.
2. Направьте DNS домена на хост.
3. В корне распакованного пакета создайте `.env` по `.env.example`. Установите `LIBO_DOMAIN=ваш-домен`. Секреты в Git и чат не отправляйте.
4. Запустите:

   ```bash
   docker compose --env-file .env -f server/compose.yaml up -d --build
   ```

5. Проверьте `https://ваш-домен/health` и `https://ваш-домен/api/cloud/features`.
6. На каждом телефоне откройте **LIBO Cloud** → адрес `https://ваш-домен/api/cloud` → включите хранилище.
7. **Сохраните файл ключа восстановления** и отметьте, что он сохранён. Этот файл предоставляет доступ к аккаунту и истории; не прикладывайте его к сообщениям или баг-репортам.
8. Добавьте собеседника по нику после его регистрации на этом же сервере.
9. В Android-настройках LIBO разрешите уведомления и отдельно включите **«Доставка в фоне»**.

Нативная служба показывает постоянное системное уведомление о соединении. Она не использует Firebase/FCM. Android Doze, ограничения батареи, отсутствие интернета и принудительная остановка могут задерживать уведомления. После force-stop приложение нужно открыть вручную. При необходимости пользователь может разрешить неограниченную работу батареи в системных настройках. Автоматического обхода ограничений Android нет.

Уведомление не содержит текста переписки. После нажатия нужно открыть чат, а при включённом локальном хранилище — сначала ввести пароль.

### Без Docker

Node.js 22.13+, `npm ci --omit=dev`, защищённые переменные окружения, `npm run server`. Внешний reverse proxy обязан предоставлять HTTPS. Сервис по умолчанию слушает `0.0.0.0:3000`. Не выставляйте этот HTTP-порт напрямую в интернет.

## Хранение, ограничения и восстановление

- `CLOUD_DB`: файл SQLite на постоянном приватном томе. В Compose это `/data/cloud.sqlite`.
- `CLOUD_QUOTA_BYTES`: по умолчанию 64 МиБ зашифрованных записей на аккаунт.
- `CLOUD_TOTAL_QUOTA_BYTES`: по умолчанию 512 МиБ зашифрованных записей на сервер. Это логическая квота, не полный размер SQLite/WAL/резервных копий.
- `CLOUD_MAX_ACCOUNTS`: по умолчанию 100 аккаунтов. Есть лимиты запросов и регистрации по IP-хэшу; их недостаточно вместо полноценной защиты от злоупотреблений в массовом публичном сервисе.
- До 20000 записей истории и статусов на аккаунт, до 16 устройств. Сеансы живут 30 дней и обновляются при открытии приложения. Токен уведомлений сохраняется при обычном повторном входе, чтобы блокировка WebView не прерывала службу.
- В чате на устройстве остаются последние 500 сообщений. Локальные заметки «Избранное», черновики, настройки оформления и их изображения не синхронизируются в облако.
- Исходящее сообщение с часами ещё только на устройстве: если отправитель закрывает приложение до передачи серверу, оно отправится при следующем открытии. Значок облака подтверждает передачу в серверную очередь.
- Ник зарегистрированного облачного профиля в этой бете фиксирован. Телефон/SMS — отдельная необязательная функция; никакой выдуманной проверки номера нет.
- Файл восстановления содержит URL сервера и случайный 256-битный секрет. Он расшифровывает серверную копию ключей. **Пароль локальной истории не защищает сам файл восстановления.** Храните файл в собственном защищённом хранилище.
- Удаление облачного аккаунта удаляет его историю, сеансы и серверную копию ключей. Копии у собеседников и локальная история на телефоне не удаляются.

Снимайте согласованные резервные копии SQLite вместе с WAL либо используйте штатный online backup. Резервные копии содержат зашифрованные сообщения, но также открытые служебные метаданные. Защитите диск, доступ к хостингу, журналы и резервные копии.

Временный sandbox Arena не является постоянным сервером; его внешний URL может требовать специальную авторизацию. Его адрес не вшивается в APK.

## API

- `POST /challenge`, `POST /session` — вход с подписью ECDSA и одноразовым challenge.
- `GET /directory/:id` — подписанный публичный набор ключей контакта; нужен полный сеанс.
- `POST /messages` — атомарная запись конвертов для получателя и отправителя, идемпотентность по автору/ID.
- `POST /control` — зашифрованные ACK/READ/READ-ACK.
- `GET /history?after=cursor` — только собственные записи, ограниченные по числу и размеру страницы.
- `GET /notifications?after=cursor` — long poll, доступен ограниченному токену, без содержимого сообщений.
- `POST /recover` — зашифрованный пакет ключей по случайному идентификатору восстановления; секрет расшифровки не отправляется.
- `GET /usage`, `PUT /blocked`, `DELETE /history`, `DELETE /account` — собственная квота, блокировки и управление аккаунтом.

Перед реальным использованием необходимы проверки на физических телефонах, мониторинг, TLS, резервирование и аудит безопасности. Физическое поведение фоновой Android-службы пока не считается проверенным браузерными тестами.
