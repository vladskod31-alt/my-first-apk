# LIBO 2.8.8: локальні з’єднання та виклики

## Один Wi-Fi або hotspot

1. Встановіть 2.8.8 на обидва телефони та відкрийте застосунок.
2. Підключіться до одного роутера; або один телефон створює hotspot, інший підключається.
3. На обох: **Налаштування → Wi-Fi · Wi-Fi Direct · NFC → Локальний канал**.
4. На другому введіть приватну IP-адресу першого, показану в діалозі, та натисніть **Підключити по Wi-Fi**.
5. Відкрийте канал зі списку, прийміть запит контакту, звірте номер безпеки. Надішліть повідомлення в обидва боки.

Порт TCP 42888, тільки приватні IPv4 10/8, 172.16/12, 192.168/16. IP може змінюватися. Якщо адрес декілька, потрібна адреса спільної мережі, не VPN. Guest Wi-Fi / AP isolation може блокувати доступ. Вимкнення локального каналу закриває сокети і Direct-групу. Виявлення LAN через mDNS та автоматичне створення hotspot не реалізовані.

## Wi-Fi Direct — експериментально

1. Увімкніть Wi-Fi, локальний канал і **Знайти пристрої Direct** на обох телефонах.
2. Надайте дозволи. Android 12 і нижче також може вимагати увімкнену геолокацію.
3. На одному телефоні оберіть другий; підтвердьте системний запит на другому.
4. Android визначає власника групи, інший учасник відкриває TCP-канал до нього.
5. Якщо з’єднання не виникло, оновіть IP-адреси та підключіться вручну до IP власника групи.

Пристрої в системному пошуку не обов’язково мають LIBO. Немає припущення, що ім’я пристрою автентифіковане. Wi-Fi Direct залежить від OEM, не перевірений фізично. Голосовий WebRTC може обрати інший мережевий інтерфейс; спільний Wi-Fi рекомендований для першого тесту.

## Голосовий виклик

Прийміть контакт і дочекайтесь значка шифрування на обох телефонах. Кнопка слухавки в шапці чату запускає виклик. Інший учасник натискає **Прийняти**; лише тоді запитується його мікрофон. Доступні mute, увімкнення відтворення (якщо autoplay заблоковано) та завершення. 60 секунд без встановленого зв’язку — тайм-аут.

SDP (разом із DTLS fingerprints) проходить через існуючий E2EE-канал. Аудіо використовує WebRTC DTLS-SRTP, **не Double Ratchet**. Локальний Wi-Fi-канал передає signaling без Інтернету, з порожнім списком STUN/TURN. Звичайний WebRTC/Bluetooth signaling для дзвінка використовує ICE-сервери налаштувань; Bluetooth не передає сам звук.

Це **foreground-only** виклики. Згортання, блокування LIBO або втрата каналу завершує виклик і зупиняє треки. Немає відео, групових викликів, телефонних номерів, фонового дзвінка, вибору аудіовиходу чи Android Telecom інтеграції. Вхідні виклики від неприйнятих/заблокованих контактів або контакту зі зміненим ключем відхиляються.

## NFC NDEF, не Android Beam

Потрібна форматована, достатньо містка NDEF-мітка (орієнтовно 256+ байт) і NFC-адаптер.

- **Перезаписати мітку**: замінює існуючий NDEF-вміст публічним peer ID та ключем LIBO. Приватних ключів/паролів там немає. Перезаписуйте лише власну мітку.
- **Прочитати мітку**: зчитує `application/vnd.libo.invite`, перевіряє запрошення, відкриває форму контакту. Підтвердіть додавання вручну.
- Закриття діалогу/втрата фокусу вимикає NFC-reader mode. При невдачі повторіть сканування.
- Немає Android Beam, емуляції NFC-картки або передачі голосу через NFC. Мітка містить контакт, не налаштування Wi-Fi.

Не довіряйте невідомим міткам. Вони можуть містити справжнє, але чуже запрошення: перевірте особу й номер безпеки.
