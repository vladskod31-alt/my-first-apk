## Как обновиться с предыдущих сборок (обязательно прочитайте)

Подпись этой сборки **не совпадает** с подписями ранних тестовых сборок (у каждой сессии
сборки свой временный ключ), поэтому Android не позволит «обновить» приложение поверх —
нужна чистая установка:

1. В старом LIBO: **Настройки → Резервная копия: экспорт текста** — сохраните JSON.
2. Удалите старое приложение. Внимание: база LIBO зашифрована ключом из Android Keystore;
   после удаления ключи уничтожаются, и старые чаты восстановить нельзя — только экспорт из п.1.
3. Установите `LIBO-2.8.7.apk` (разрешите установку из неизвестных источников).
4. **Настройки → Восстановить из копии** — импортируйте JSON как архив только для чтения.
   Ключи и шифрование создаются заново: обменяйтесь с собеседниками новыми личными кодами.

В браузере (веб-версия) профиль живёт в IndexedDB того же origin и сохраняется между сборками.

## Что в 2.8.7

### Безопасность (линейка LIBO SECURITY 2.8.2 → 2.8.4 → 2.8.7)
- Сквозное шифрование: X25519 (обмен ключами), Ed25519 (идентичность и подписи),
  Double Ratchet (прямая секретность), ChaCha20-Poly1305 (сообщения) — на аудированных
  библиотеках `@noble/*`, без самописной криптографии. Подробности: `docs/SECURITY_ARCHITECTURE.md`.
- Закрепление ключа собеседника: смена идентичности видна в чате и требует подтверждения.
- Защита от даунгрейда: после E2EE-рукопожатия открытый текст от этого пира игнорируется.
- Хранилище, зашифрованное в покое: чаты и идентичность устройства — AES-256-GCM в IndexedDB;
  ключ хранилища обёрнут аппаратным Android Keystore (`libo-vault-v1`) или неизвлекаемым
  WebCrypto-ключом в браузере.
- Экран блокировки: PIN + биометрия (BiometricPrompt / системный диалог подтверждения),
  автоблокировка по таймауту, счётчик попыток.
- `FLAG_SECURE`: скриншоты и превью в недавних приложениях заблокированы.

### Bluetooth P2P — личные сообщения без интернета
- Прямой радиоканал между двумя телефонами рядом: классический RFCOMM + BLE-объявление/скан.
- Поверх Bluetooth работает тот же подписанный hello и Double Ratchet — сквозное шифрование
  не зависит от транспорта.
- Диалог «Bluetooth P2P»: приём подключений, «Сделать видимым», поиск устройств, список
  активных каналов с открытием чата и разрывом связи. Контакт не обязан быть добавлен заранее —
  первый Bluetooth-контакт приходит как запрос на общение.
- В браузере Bluetooth недоступен — там остаётся WebRTC; диалог честно об этом сообщает.

### Уведомления и фоновый режим
- Системный канал «Сообщения» (IMPORTANCE_HIGH): уведомления о новых сообщениях, когда
  приложение свёрнуто или открыт другой чат; тап по уведомлению открывает нужный чат.
- Приватность: переключатель «Показывать текст» (иначе только «Новое сообщение»),
  на экране блокировки текст скрыт всегда (VISIBILITY_PRIVATE + publicVersion).
- Кнопка «Проверить уведомления» в настройках + понятный статус разрешения.
- В браузере — Web Notifications с тем же сценарием.
- Фоновый режим (опционально): foreground-сервис `KeepAliveService` с типом `specialUse`
  и тихим уведомлением «LIBO на связи»; включается только вручную.

### Интерфейс и анимации (2.8.5 + финальный проход 2.8.7)
- Округлённый интерфейс: диалоги 28px, пузыри сообщений 20px, строки чатов 18px,
  композер 22px; на мобильном диалоги становятся нижним «листам» с ручкой.
- Ripple-волна от точки касания на всех нажимаемых поверхностях + **тактильный отклик**
  (haptic tick на нажатие, success-вибрация на отправку) — новое в этой сборке.
- Пружинные кривые (`--spring`), «дыхание» кнопки на приветственном экране, свечение
  фокуса, анимация отправки, радар поиска Bluetooth, бегущая полоса сканирования.
- Финальный проход: блик-«shine» на основных кнопках при наведении, амбиентные блобы
  на приветственном экране, подъём строки чата при наведении, пульс онлайн-индикатора.
- `prefers-reduced-motion` отключает все декоративные анимации.
- 20+ функций в стиле Telegram: форматирование текста, спойлеры, тихая отправка,
  никнеймы, закреп/архив чатов, отложенные сообщения, стикеры, опросы, реакции,
  ответы и пересылка, обои и размер шрифта, темы, активные сессии и ротация ключей,
  заблокированные контакты.

### Иконка и сплэш — исправление главной проблемы первой 2.8.7
Причина дефекта: битмапы кладлись в `mipmap-anydpi-v26` (anydpi-ресурсы не масштабируются
по плотности и на части лаунчеров не отображались), а первое окно наследовало тёмный фон темы.
Исправление:
-Legacy-иконки и слои адаптивной иконки — PNG в каждой плотности (mdpi…xxxhdpi),
  фон адаптивной иконки — векторный градиент, `monochrome`-слой для тематических иконок Android 13+.
- Стартовая тема `AppLaunchTheme` с брендовым `windowBackground` (логотип на фиолетовом поле) —
  первый кадр больше никогда не чёрный.
- Android 12+: системный SplashScreen API (`windowSplashScreenBackground`,
  `windowSplashScreenAnimatedIcon` внутри safe-zone 66dp) + ночная палитра.
- Поверх WebView — нативный анимированный `SplashView` (логотип, кольцо, пульс), который
  уходит по сигналу веб-приложения `uiReady()`, по завершении загрузки страницы или через 6 с.
- Веб-иконки (PWA): `icon.svg`, 192/512, maskable-вариант и `manifest.webmanifest`.
