# Зеркало APK для тега релиза

`LIBO-2.8.3.apk` — подписанный установочный файл для Android 8.0+ (API 26+), пакет
`app.libo.messenger`, versionCode 20803, версия **2.8.3**: двенадцать функций в стиле
Telegram (из 2.8.2) плюс новая архитектура безопасности вместо прежнего MT-слоя с
AES-256 — настоящий E2EE (X25519 + Ed25519 + ChaCha20-Poly1305, Double Ratchet),
шифрование базы ключом Android Keystore и запрет отправки открытого текста в сеть.

Размер файла: 317 819 байт

SHA-256 файла: `9be21beafa55600350873114429edf57a8c527a6767248bf07ef814a8513f456`
(см. `SHA256SUMS.txt` рядом).

Тот же файл приложен к релизу `v2.8.3` как его файл:
https://github.com/vladskod31-alt/my-first-apk/releases/download/v2.8.3/LIBO-2.8.3.apk
(загружено workflow `publish-asset.yml` из GitHub Actions). Этот каталог — зеркало на
случай недоступности `uploads.github.com`.

Что нового в 2.8.3 и как проверять подпись — в [RELEASE_NOTES.md](../RELEASE_NOTES.md) и

> ⚠️ Важно о подписи 2.8.3.
>
> Релизный кейстор хранится владельцем вне репозитория (см. RELEASE_NOTES.md) и не
> передаётся в это окружение. Поэтому собранный здесь APK подписан **временным
> тестовым ключом** песочницы, отпечаток сертификата
> `cc4d906f4cd1b664d56091d8bbd733fd5e1aef46d3313fb6453a863b033d1ab8`
> (CN=LIBO Release, O=LIBO Messenger, RSA-4096, схемы v2+v3).
>
> Это не ключ 2.8.0 (`f4e4b3e5…dba4`), не ключ зеркального APK 2.8.1 (`d5e09a20…5e9a`) и
> не ключ зеркального APK 2.8.2 (`d6bc33ca…7678e`). Значит, Android **не установит этот
> файл поверх** уже стоящей LIBO, подписанной другим ключом: перед установкой сделайте
> Настройки → «Резервная копия: экспорт текста», удалите прежнюю версию LIBO, установите
> 2.8.3 и импортируйте копию (она откроется как архив только для чтения). Для свежей
> установки дополнительных действий не нужно.
>
> APK, собранный в GitHub Actions с релизными секретами (`release.yml`), подписывается
> ключом владельца и ставится поверх установленной версии без потери истории.
