# LIBO 2.3

Тестовий Android-месенджер: нік, контакти та близькі, AES-256, налаштовуваний інтерфейс і необов’язковий власний сервер доставки.

> **Код LIBO 2.3 підготовлено до публічного pull request за явною згодою власника від 12 вересня 2026.** Після попередження про видимість Public власник підтвердив публікацію коду. APK, ZIP, локальні сторінки з вбудованим APK, ключі, паролі та бази до PR не входять. Умови використання компонентів і нових змін визначає `LICENSE`; відкритість перегляду репозиторію не змінює цих умов.

> **Іконка ще очікує оригінальний файл.** JPG підходить, PNG не потрібен. Картинка з чату відображається в повідомленні, але сам JPG недоступний у робочій папці. Поточна збірка має попередню іконку — її не підмінено приблизним зображенням. Для точного встановлення потрібен доступний JPG, наприклад усередині ZIP. Див. `branding/README.md`.

## Що є у 2.3

- Кнопки-капсули, п’ять палітр, власний колір кнопок, фон усього застосунку та колір вихідних повідомлень.
- Окреме оформлення кожного чату: колір, фотографія на фон, затемнення. Налаштування й фото зберігаються локально; за ввімкненої парольної історії вони теж шифруються.
- Розмір тексту повідомлень, світла/темна/системна тема, RU/UK/EN, офлайн-каталог Emoji 15.0 та 3720 SVG.
- Обов’язковий нік, контакти, близькі, локальні імена й номери. Немає запрошень кодами. Введений номер не позначається підтвердженим без справжнього SMS-провайдера.
- Прямий режим PeerJS/WebRTC із зашифрованим транспортом і перевіркою ключів збережено.
- **LIBO Cloud**: підписані зашифровані конверти, серверна черга для відсутнього отримувача, окрема зашифрована копія для відправника, відновлення ключів та історії з файлу відновлення.
- **Android-сповіщення**: дозвіл `POST_NOTIFICATIONS`, окрема служба фонового з’єднання, канали сповіщень, обмежений токен у Android Keystore, повернення до служби після завантаження ОС. Текст повідомлення в системне сповіщення не включається.
- Окремі статуси: на пристрої → збережено на сервері → збережено отримувачем → показано у прийнятому чаті. Позначки прочитання можна вимкнути.

## Важливо про сервер і фон

Користувач обрав **підготувати APK та сервер без наявного хостингу**. Серверна частина реалізована й перевірена локально, але постійний сервер не розгорнутий. APK не створює хостинг автоматично; у production-конфігурації адреса хмари порожня.

- Без хмари працює прямий режим: обидва клієнти мають бути відкриті.
- З налаштованою хмарою відправник після значка хмари може закрити застосунок: повідомлення вже збережено на сервері.
- Якщо отримувач без інтернету, повідомлення чекає на сервері до повернення зв’язку. Доставити його на фізично відключений телефон неможливо.
- Якщо вихідне повідомлення ще має годинник, воно тільки на пристрої. Якщо закрити застосунок до передачі серверу, відправлення продовжиться після наступного відкриття.
- Фонова доставка використовує **Android foreground service**, не Firebase/FCM. Постійне системне сповіщення про з’єднання — частина цієї роботи. Doze, обмеження батареї, force-stop та політики виробника можуть затримувати сповіщення.

Налаштування: підключити однаковий сервер на обох пристроях, зберегти файл ключа відновлення, дозволити сповіщення Android та ввімкнути «Доставка у фоні». Докладно: [server/CLOUD_2.3.md](server/CLOUD_2.3.md).

## APK і сумісність

- Версія `2.3.0`, код `20300`, пакет **`app.libo.messenger.preview23`**, назва **LIBO 2.3**.
- Android 8.0+ та актуальний Android System WebView.
- Це окрема тестова інсталяція: попередні ключі підпису недоступні. **Не видаляйте попередню LIBO з важливим листуванням.** Дані старих пакетів не переносяться автоматично.
- Файл відновлення Cloud 2.3 призначений для хмарного аккаунта 2.3; він не відновлює локальну історію зі старої 2.1.
- Тестовий підпис не є виробничою. Для майбутніх оновлень тим самим пакетом потрібен постійний ключ підпису власника.

Результати приватної передачі формуються в `deliverables/libo-2.3/`: APK, ZIP з APK, контрольна сума та окремий ZIP серверної частини. Жоден скрипт цієї передачі не викликає git push або публікацію релізів.

## Розробка та перевірки

Node.js 22.13+:

```bash
npm ci
npm run dev
npm test
npm run test:e2e
npm run build
```

Dev-сервер слухає `0.0.0.0:5173`. На одному origin працюють Vite, `/peerjs`, `/api` для необов’язкового SMS та `/api/cloud` для локальних тестів хмари. Це не постійний хостинг. Для різних користувачів потрібні окремі браузерні профілі/контексти.

Один профіль одночасно працює в одному вікні; Web Locks захищає міграцію локального сховища. У dev-режимі підвищено ліміти створення тестових аккаунтів; production використовує суворіші значення.

### Android-збірка

Java 17, SDK 35, Build Tools 35.0.0, Python 3. Запасний Linux x64 toolchain:

```bash
node scripts/bootstrap-toolchain.mjs "$HOME/.local/share/libo-toolchain"
export JAVA_HOME="$HOME/.local/share/libo-toolchain/runtime/jre"
export LIBO_TOOLCHAIN="$HOME/.local/share/libo-toolchain/android"
./scripts/build-apk-local.sh
npm run test:apk-assets
npm run package:private
```

Бінарні інструменти перевіряються за зафіксованими хешами. Ключ тестового підпису та файл пароля — **поза Git**, у `$HOME/libo-private-signing-23/`. Власник має зберігати свої виробничі ключі окремо й безпечно. Ніколи не надсилайте їх у чат або репозиторій.

За наявності звичайного Android SDK також доступно `./gradlew assembleDebug lintDebug`. Така debug-збірка може мати інший ключ, ніж локальний запасний скрипт; її не слід автоматично вважати сумісним оновленням уже встановленого тестового APK.

### Встановлення саме надісланого зображення

JPG підтримується без стороннього сервісу:

```bash
node scripts/apply-icon.mjs /path/to/icon.jpg
./scripts/build-apk-local.sh
```

Скрипт локально створює Android PNG/adaptive-іконки й веб-іконку, зберігаючи оригінал. Потрібен доступний файл; із самого відображення картинки в чаті він не вигадує оригінальні байти.

## Межі захисту

Це **неаудована бета**, не Signal і не сертифікований захищений продукт. Хмарний режим не реалізує Double Ratchet: постійний ключ отримувача має іншу модель захисту, ніж тимчасові ключі прямого з’єднання. Перший контакт використовує TOFU; звіряйте відбитки ключів довіреним способом.

Парольна локальна історія — окрема опція. До її ввімкнення особисті записи не мають додаткового шифрування застосунку. Пароль і секрет відновлення не надсилаються серверу відкритим текстом. Файл відновлення Cloud містить секрет доступу і **не** захищений паролем локальної історії.

Локально — до 100 чатів та 500 повідомлень у чаті. Типова квота сервера — 64 МиБ на аккаунт, 512 МиБ сумарно, до 20000 записів повідомлень і статусів на аккаунт. Локальні нотатки, чернетки й оформлення не синхронізуються в хмару. Експорт тексту є незашифрованим JSON з попередженням.

Фізичний Android, реальні мобільні мережі, Doze і системні діалоги ще потребують перевірок. Умови: `LICENSE`; обов’язкові повідомлення компонентів: `THIRD_PARTY_NOTICES.md`.
