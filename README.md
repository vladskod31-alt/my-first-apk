# LIBO

![Иконка LIBO](web/public/icon-512.png)

**LIBO — личный мессенджер для переписки один на один.** Сообщения и фотографии идут
напрямую между двумя устройствами по WebRTC: без сервера переписки, без регистрации по
телефону и без облачной истории. Личный код устройства — единственный адрес.

Текущая версия: **2.8.2** (тестовый релиз для Android 8.0+). Ссылки на скачивание,
контрольные суммы и отпечаток подписи — в
[RELEASE_NOTES.md](RELEASE_NOTES.md).

## Возможности

- Личный код устройства: копирование, QR-код, системное меню отправки приглашения.
- Чаты один на один: текст до 4000 символов, сжатые фотографии JPG/PNG/WebP, ответы,
  индикатор «печатает…».
- Голосовые сообщения, файлы и короткие видео, правки, удаление для обоих, закрепы,
  реакции LIBO SVG-emoji, близкие контакты, статус «был(а) в сети», архивы из резервных
  копий, кнопка-щит со сводкой безопасности.
- MT-слой защиты в стиле MTProto 2.0 (ECDH P-256 + AES-256-GCM, защита от повторов,
  отпечаток ключа в диалоге безопасности), папки чатов, пересылка, секретный таймер,
  галочки прочтения, опросы, код-замок PIN, фоны переписки, мультивыбор, глобальный
  поиск сообщений, без звука для чата.
- Подтверждение доставки «✓✓» после сохранения сообщения на устройстве получателя.
- Очередь исходящих: написанное офлайн уходит после возвращения собеседника.
- Локальная история и черновики, «Избранное», поиск, непрочитанные, блокировка.
- Темы светлая/тёмная/системная, профиль, звук сообщений, экспорт текста в JSON.
- Код сверки собеседника (короткая строка аутентификации) в меню чата.
- Разметка и спойлеры, цитаты, хэштеги, жесты, закрепы и архив чатов, отложенная и тихая
  отправка, опросы-квизы, медиа-панель чата, ночная тема по расписанию.
- Собственный сигнальный сервер и TURN при необходимости.

## Ограничения (честно)

- Оба собеседника должны держать приложение открытым: фоновых push-уведомлений и
  облачной истории нет.
- Личность собеседника подтверждается кодом сверки и сверкой личного кода по доверенному
  каналу, а не криптографически автоматически.
- По умолчанию используются публичные PeerJS- и STUN-серверы; для строгих NAT нужен TURN.
- Это тестовый релиз: APK не запускался на физическом устройстве в среде сборки.
- Подробный список с планом работ — в [KNOWN_ISSUES.md](KNOWN_ISSUES.md).

## Безопасность

Транспорт WebRTC защищён DTLS. Локальная база не зашифрована отдельно. Подпись APK —
релизный ключ RSA-4096; отпечаток сертификата и порядок проверки — в
[RELEASE_NOTES.md](RELEASE_NOTES.md) и [SECURITY.md](SECURITY.md). Об уязвимостях
сообщайте по инструкции из `SECURITY.md`, без публичного issue.

## Разработка

Нужен Node.js 22+. Веб-часть (та же, что внутри APK) запускается локально:

```sh
npm ci
npm run dev        # http://127.0.0.1:5173 со своим локальным signaling /peerjs
npm test           # модульные тесты
npm run test:e2e   # браузерные сценарии Playwright (Chromium ставится из npm)
npm run build      # production-бандл в dist/
```

Сборка APK без Gradle (для сред без доступа к SDK Android):

```sh
node scripts/bootstrap-toolchain.mjs   # внешние инструменты с закреплёнными SHA-256
# Скопируйте JAVA_HOME и LIBO_TOOLCHAIN из вывода команды выше.
./scripts/build-apk-local.sh           # релизный APK и SIGNING.txt в artifacts/
```

Gradle-сборка (CI и обычные машины с SDK Android):

```sh
./gradlew assembleDebug     # или assembleRelease с собственной подписью
```

Подробности проверок и окружения — в [TESTING.md](TESTING.md). Автоматическая сборка и
публикация релизов — в [.github/workflows](.github/workflows).

| --- | --- |
| `web/` | Интерфейс и логика мессенджера (P2P-транспорт, хранилище, протокол) |
