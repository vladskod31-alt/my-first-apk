# LIBO Messenger

Личный мессенджер для Android и браузера. Переписка один на один через WebRTC, без регистрации по номеру телефона.

**Версия:** 2.0.0-beta.1 · **Android:** 8.0+ с обновлённым Android System WebView.

[Релизы и APK](https://github.com/vladskod31-alt/my-first-apk/releases) · [Шаблон автосборки](ci/android.yml) · [Результаты проверок](TESTING.md) · [Что нового и ограничения](RELEASE_NOTES.md)

## Быстрый старт

1. Установите APK из GitHub Releases на оба телефона.
2. В настройках укажите своё имя. Откройте карточку **«Ваши люди. Ваш LIBO.»** и скопируйте личный код.
3. На втором устройстве нажмите **«Новый чат»**, вставьте код первого устройства и добавьте контакт.
4. На принимающей стороне откройте появившийся чат и примите запрос.
5. **Оба приложения должны быть открыты.** Если телефон не в сети, исходящее сообщение остаётся в очереди на устройстве отправителя.

QR-код — настоящий и считывается внешним сканером. Встроенного сканера в этой бете нет.

### Возможности

- Личные сообщения, фотографии (JPEG/PNG/WebP, исходный файл до 12 МБ, сжатие до 1280 px), ответы, индикатор набора.
- Статусы: часы — очередь; ✓ — отправлено в канал, без подтверждения; ✓✓ — **сохранено на устройстве получателя**, не прочитано.
- Подтверждение только после завершения IndexedDB-транзакции, повторная отправка и дедупликация по ID сообщения.
- История, текстовые черновики, непрочитанные, локальное «Избранное», поиск и блокировка по личному коду.
- Профиль, светлая/тёмная/системная тема, необязательный звук входящих сообщений.
- Текстовый экспорт JSON в браузере или через системный выбор места сохранения Android. **Без фото, личного кода и настроек. Импорт не предусмотрен.**
- Лимиты: 4000 символов в сообщении, до 100 чатов, последние 500 сообщений в каждом чате. При заполнении удаляются старые входящие/доставленные записи; недоставленная очередь не вытесняется.

## Что синхронизируется с GitHub

**Только исходный код, сборки и опубликованный APK. Переписка, фотографии, черновики и настройки не загружаются в GitHub.** Не используйте issues, git или публичные Releases для хранения личных сообщений.

Исходный `LIBO_v-1.4.6_SUPER_MEGA_STABLE-6.html` сохранён **без изменений**. Новая модульная версия находится в `web/`; автоматической миграции старых локальных данных нет.

## Ограничения и безопасность

Это первая **бета**, не замена готовому производственному мессенджеру:

- Нет push-уведомлений, фонового Android-сервиса, звонков, групп, облачной истории, восстановления профиля или синхронизации нескольких устройств.
- История и личный код находятся в IndexedDB WebView/браузера. Текстовые черновики — в localStorage. Удаление приложения/данных удаляет их. База не шифруется отдельно от защиты самого устройства.
- По умолчанию APK использует публичный брокер **`https://0.peerjs.com`** для signaling и публичные STUN-серверы Google/Cloudflare. Доступность этих сервисов не гарантируется.
- Если сеть не разрешает прямое WebRTC-соединение (часть мобильных сетей, симметричный NAT, VPN), нужен собственный TURN-сервер. В бесплатную сборку TURN не включён. Адрес, логин и пароль можно указать в настройках.
- WebRTC защищает канал шифрованием DTLS, но здесь нет проверяемых долговременных ключей личности/Double Ratchet. Имя может быть любым; личный код следует сверять через доверенный канал. Прямое P2P-соединение может раскрывать IP собеседнику. Signaling/STUN/TURN видят сетевые метаданные. **Анонимность и аудит безопасности не заявляются.**
- Внешние изображения и HTML-сообщения не исполняются: протокол принимает только ограниченный текст и raster data URL, все пользовательские строки выводятся через `textContent`.
- Android загружает только bundled-ресурсы через локальный HTTPS origin; внешние страницы открываются в браузере, не в WebView с native bridge. Файловый доступ отключён, есть CSP; выбор фото и экспорт используют системные диалоги, без разрешений на всё хранилище.
- Публичный код — средство добавления контакта, не пароль. Не публикуйте его, если не хотите получать запросы. Блокировка действует на код, не на личность человека.

### Подпись APK

Первый APK — **тестовая debug-сборка** (пакет **`app.libo.messenger.beta`**), подписанная локально созданным тестовым ключом. В этой сессии APK собран скриптом `scripts/build-apk-local.sh` без Gradle/Actions; эквивалентная стандартная сборка — `assembleDebug`. Это не production-релиз и не публикация в Google Play.

Секретный ключ не добавлен в Git. У подключения репозитория в текущей сессии нет разрешения управлять GitHub Actions Secrets. Также GitHub отклонил загрузку workflow из-за отсутствия разрешения `workflows`. Поэтому постоянная release-подпись и активная автосборка не настроены; следующая сборка может иметь другой сертификат и потребовать удаления старой версии. Перед удалением сохраните важные данные отдельно; текстовый экспорт не является восстановлением профиля или базы.

Для производственного выпуска владелец должен создать и безопасно сохранить release-keystore, добавить его **через GitHub Settings → Secrets and variables → Actions**, настроить `signingConfigs` в `app/build.gradle` и заменить `assembleDebug` на `assembleRelease`. Никогда не публикуйте keystore или пароль в репозитории, issues, логах или чате.

## Разработка и проверки

Требуется Node.js 22+:

```sh
npm ci
npm test                 # unit-тесты валидатора, границ и экспорта
npm run dev              # http://localhost:5173
npm run test:e2e         # браузерные сценарии, в том числе два реальных WebRTC-клиента
npm run build            # автономный bundle в dist/
```

Dev-сервер слушает `0.0.0.0:5173`, допускает preview-host `*.e2b.app`. Он включает **временный локальный signaling на `/peerjs`**, поэтому два открытых preview-клиента можно проверять без внешнего облака. Vite и signaling работают на одном origin; браузер не обращается к sandbox localhost. Dev-режим не является постоянным хостингом для установленного APK.

Production-bundle использует публичный PeerJS-сервер. Если соединяете preview и APK, **задайте одинаковый сигнальный сервер в обоих клиентах**. В production принимается HTTPS; HTTP разрешён только на совпадающем loopback-origin для локальных тестов.

`@sparticuz/chromium` используется только для headless-тестов Linux и не попадает в APK. Для собственной установленной копии Chromium задайте `CHROMIUM_PATH`.

### Сборка Android локально

Нужны JDK 17, Android SDK platform 35/build-tools 35.0.0 и принятые Android SDK licenses:

```sh
export ANDROID_HOME=/path/to/android-sdk
export JAVA_HOME=/path/to/jdk-17
npm ci
npm run build
./gradlew assembleDebug lintDebug
# app/build/outputs/apk/debug/app-debug.apk
```

Gradle 8.9 загружается wrapper-ом с проверкой SHA-256; Android Gradle Plugin 8.7.3. В APK включены HTML, JS, CSS, QR-библиотека и шрифты — интерфейс и «Избранное» открываются без интернета. Для реальной переписки интернет обязателен.

### Локальная сборка без Actions / Gradle download domains

В текущей среде Android SDK/Gradle download domains недоступны, а у GitHub-подключения нет разрешения `workflows`. APK действительно собран локально альтернативным маршрутом:

```sh
node scripts/bootstrap-toolchain.mjs
# Скопируйте export JAVA_HOME и export LIBO_TOOLCHAIN из вывода.
./scripts/build-apk-local.sh
# artifacts/LIBO-2.0.0-beta.1.apk и artifacts/SHA256SUMS.txt
```

Нужны Linux x64, Node 22, `gh` и `tar`. Скрипт загружает инструменты **вне репозитория**: Android SDK stubs/D8/apksigner/zipalign из закреплённой ревизии MIT App Inventor, AAPT2 из закреплённой ревизии Apktool, ECJ 4.5.1 и пакет Temurin JRE 17.0.17. Источники и контрольные суммы находятся в `scripts/toolchain-sources.json`; проверяются SHA-256 инструментов и SHA-512 архива JRE. Бинарные инструменты, ключи и промежуточные файлы не коммитятся. Исключение: запрошенный маленький APK первой беты сохранён в `downloads/`, поскольку загрузка assets через `uploads.github.com` завершилась сетевой ошибкой. Ссылка привязана к тегу релиза, а не к изменяемому содержимому ветки.

Выполняются компиляция ресурсов, Java → D8 → APK, zipalign и проверка цифровой подписи. **Это не означает запуск APK на физическом телефоне.** Подробности и непроверенные сценарии — в [TESTING.md](TESTING.md).

### GitHub Actions / следующий релиз

Готовый workflow сохранён как **`ci/android.yml`**, вне `.github/workflows`, поскольку GitHub запрещает этому подключению создавать workflows. Это шаблон, **он пока не запускается автоматически**.

После переподключения GitHub в Arena с разрешением **Workflows** переместите шаблон в `.github/workflows/android.yml`. Он выполняет unit- и браузерные тесты, сборку web assets, Android lint, сборку APK и проверку `apksigner`; сохраняет APK и `SHA256SUMS.txt` как Actions artifact.

Для новой публикации:

1. Обновите версии в `package.json`, `package-lock.json`, `web/lib/core.mjs`, `app/build.gradle`, ссылку `APK_URL` и release notes. Увеличьте `versionCode`. При публикации бинарных assets через Actions указывайте `APK_URL` вида `https://github.com/<owner>/<repo>/releases/download/v<version>/LIBO-<version>.apk`.
2. При активном workflow запустите **Android APK**, выбрав рабочую ветку и `publish=true`, либо используйте commit message с маркером **`[publish-apk]`**.
3. Workflow создаст **GitHub prerelease** `v<version>` с APK и SHA-256. Существующий release не перезаписывается. Без Actions можно собрать локально и опубликовать через `gh release create --target <commit>`.

## Структура

```text
web/                 интерфейс и P2P-протокол
web/lib/             валидация, IndexedDB, транспорт
app/                 нативная Android-оболочка (Java)
scripts/             dev-сервер с локальным signaling
tests/               unit- и браузерные проверки
ci/                  шаблон GitHub Actions (пока не активирован)
```

Зависимости перечислены в `package-lock.json`; лицензионные уведомления — в `THIRD_PARTY_NOTICES.md`. Производственные signing keys, node_modules и build artifacts не хранятся в Git. Единственное намеренное бинарное исключение — запрошенный APK первой беты в `downloads/`; последующие APK рекомендуется хранить в Releases.
